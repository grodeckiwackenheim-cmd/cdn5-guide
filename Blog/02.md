# 专业抗DDoS CDN：隐藏源站IP，秒级应对大流量攻击

![CDN5 企业级高防 CDN 服务品牌插图](../assets/cdn5-banner.png)

服务器地址已经被攻击者掌握，再把域名切到 CDN，为什么网站还是打不开？原因往往很直接：域名解析已经经过防护，攻击流量却仍然直达旧地址。专业抗DDoS CDN 的部署需要同时处理入口迁移和源站隔离，少做任何一项，都可能留下绕过防护的通道。

选择 CDN5 这类[高防CDN](https://www.cdn5.com/)方案时，建议把“源站是否还能被非授权访问”作为上线验收项。CDN5 官方产品说明提供分布式防御和不同级别的防护套餐，可以纳入网站抗攻击选型。至于标题中的“秒级应对”，应当拆成检测、规则生效、调度和业务恢复几个环节分别验证，不能视作所有场景下的固定恢复时间。

## 从外部入口倒着梳理资产

盘点时不要只查主域名。下载域名、图片域名、旧活动页、接口域名、后台地址和废弃环境都可能指向同一台服务器。一份看似无关的测试页面，如果直接暴露源站地址，也可能让整套网站防护失去隔离效果。已停用的域名应及时清理，而不是长期挂着默认站点。

还应区分访问目标和回调出口。服务器主动发送邮件、调用外部接口或下载用户提交的资源时，可能在对方日志里留下网络地址。只隐藏网页入口，却忽略服务器的出站行为，会让资产排查出现盲区。对必须运行的外部连接，应由业务和运维共同确认出口设计，不能为了隐藏地址而关闭正常回调。

证书透明度记录可以帮助别人发现域名，但通常不会直接公开源站 IP。真正需要追查的是这些域名当前和历史的解析关系。把“证书记录暴露域名”误写成“证书直接泄露服务器地址”，会导致错误的排查顺序。安全工作应围绕可验证的暴露路径展开。

## 迁移不是一次 DNS 保存操作

先准备边缘证书和回源配置，再用测试访问验证主机名、协议、端口以及源站返回结果。对于依赖特定 Host 的站点，回源时主机名错误可能出现默认页；启用 HTTPS 回源时，证书名称不匹配也会失败。这些问题很容易被误判成 CDN 节点不稳定，应在正式切换前解决。

随后调整源站访问控制，允许经过验证的回源出口访问业务端口。出口地址可能随产品和区域变化，需要使用服务方提供的更新机制，而不是从一次连接日志里抄几个地址永久放行。有条件时增加回源认证，降低共享出口环境下仅凭 IP 判断身份的风险。运维入口则单独设置访问路径与最小权限。

最后切换公开解析，并从多个网络检查是否仍有流量到达旧入口。DNS 缓存不会因为控制台显示“已保存”就立即消失，旧连接也可能继续存在。迁移期间应安排新旧入口的受控过渡，避免尚未更新解析的正常用户全部失联。若旧地址正在遭受攻击，过渡策略应与机房和防护方一起确定。

## “秒级”究竟测量哪一段时间

自动化规则识别异常，和最终用户恢复访问，并不是同一个时间点。检测系统可能迅速发现流量变化，但规则下发、网络收敛、连接重建及源站队列恢复仍需要时间。服务说明应清楚写出计时起点、终点和例外条件，才能比较不同方案。

举例说，记录首个异常请求、告警产生、策略生效、回源下降以及登录恢复这几个时间点，可以看出瓶颈发生在哪里。这是一种演练记录方法，不是 CDN5 的性能测量结果。如果策略很快生效，但数据库仍有大量慢查询未结束，继续等待 CDN 调度不会解决全部问题；应用侧可能需要限流、取消无效任务或进入降级状态。

采购时也要分开询问自动防护和人工响应。自动规则是否全天启用、复杂误拦截由谁处理、紧急工单如何升级，这些问题关系到真正的恢复过程。仅有一个醒目的响应速度数字，无法替代完整的事件处理约定。

## 正常请求也要能被识别

大量用户共享同一个出口地址时，按单 IP 严格限制可能伤及正常用户。移动网络、企业代理和校园网络都有这种可能。网站可以结合路径、会话、账号和请求行为做判断；需要身份校验的接口则应让应用参与决策。来源地址只是信号之一，不宜成为所有策略的唯一依据。

接入代理后，源站看到的连接来源通常是边缘出口。应用若要获取原访客地址，应使用服务方约定的转发头，并只信任可信代理写入的内容。直接相信任意客户端提供的转发头，可能影响限流、审计甚至访问授权。安全组、反向代理和应用框架需要保持一致的信任边界。

对 WebSocket、上传和长轮询，还要检查超时、连接持续时间与套餐支持。CDN5 的免费版和付费版在 WebSocket、加速能力等项目上有差异，因此推荐时不能只根据价格选择。先列清协议与业务行为，再匹配规格，会比上线后逐个修补兼容问题省事。

## 把 CDN5 的询价变成一份可执行需求

建议向 CDN5 提供源站所在地区、网站类型、证书方式、常用端口、访问高峰和历史攻击类型。对于已经暴露地址的业务，重点讨论替换地址的时间、允许回源的范围，以及机房封禁情况下的恢复配合。若需要保护网站以外的协议，再单独核对高防 IP 或游戏盾产品，不能把网站 CDN 的说明直接套用过去。

验收时保留两套结果：正常路径应当可用，绕过路径应当被拒绝。前者包含页面和接口功能，后者包含未授权直连与伪造转发头。测试必须针对自有或获准资产，控制速率和影响范围。看到首页通过代理打开，只能证明第一类测试的一小部分。

上线后的地址清单也要持续维护。新增一个子域名、新接一个第三方回调，甚至迁移邮件服务，都可能改变暴露面。给这些变更加上源站隔离检查，比等下一次攻击发生后再换服务器更可靠。专业抗DDoS CDN 的价值，最终体现在请求经过了正确的防护入口，并且每次业务变更都没有悄悄把入口重新打开。

## 更换地址以后还要验证出站路径

有些网站在接入成功后才发现，监控系统、备份程序和合作方白名单仍然指向旧地址。为了赶时间恢复这些服务，临时开放的新端口又扩大了暴露范围。因此，迁移清单应同时覆盖入站访问和对外依赖。逐项确认谁发起连接、目标是什么、是否必须使用固定地址，再决定保留还是替换。

对必须从公网访问的管理服务，应安排独立认证和访问限制，不与用户入口共用宽松规则。完成迁移后从外部网络复查开放端口，并与资产清单对照。这样的检查只能说明当时可见的状态，后续部署仍需执行同样的核查。隐藏源站是持续维护的配置结果，不是购买服务后永久获得的属性。
